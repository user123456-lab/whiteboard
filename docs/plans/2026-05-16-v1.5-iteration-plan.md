## 七、Agent 执行分工

采用 3 个 Agent 协作模式：

```
┌─────────────────────────────────────────┐
│          Agent-0: 总审 (Review)          │
│  审查两个子Agent代码，确保接口对齐       │
│  验收功能完整性，最小化修改原则把关      │
└────┬───────────────────────┬────────────┘
     │                       │
┌────▼──────────┐   ┌───────▼───────────┐
│ Agent-1: 前端  │   │ Agent-2: 后端      │
│ 负责所有       │◄─►│ 负责后端协议+存储  │
│ 前端新功能     │讨论│ 变更              │
│                │   │                   │
│ 涉及文件:      │   │ 涉及文件:          │
│ TextEditor.tsx │   │ main.py           │
│ GridBackground │   │ room_manager.py   │
│ EraserTool.ts  │   │                   │
│ ToolManager.ts │   │ (仅 B2 乐观锁)    │
│ Toolbar.tsx    │   │                   │
│ WhiteboardCa-  │   │                   │
│   nvas.tsx     │   │                   │
│ RectangleTool  │   │                   │
│ CircleTool.ts  │   │                   │
│ ArrowTool.ts   │   │                   │
│ types/index.ts │   │                   │
│ useCanvasStor- │   │                   │
│   e.ts         │   │                   │
│ websocket.ts   │   │                   │
└────────────────┘   └───────────────────┘
```

### 执行流程

1. **Agent-0（总审）** 启动 Agent-1（前端）和 Agent-2（后端）并行编码
2. **Agent-1（前端）** 实现全部 6 项功能的前端部分（E1/A1/A2/D3/C1/B2 前端）
3. **Agent-2（后端）** 实现 B2 乐观锁的后端部分（唯一涉及后端的功能）
4. 编码完成后，**Agent-1 和 Agent-2 互相讨论**：检查协议字段是否一致（expectedVersion、fill、version），验证接口对齐
5. **Agent-0（总审）** 审查双方代码：确认最小化修改原则、检查已有功能是否被破坏、最终验收

### 最小化修改原则

- 新增字段使用 `?` 可选类型（`fill?`、`version?`），不破坏旧数据
- 新增组件独立文件，不侵入已有组件
- 协议消息增加新字段时，后端做 `None` 默认值兜底
- 已完成的工具/组件不做重构性修改，仅增加必要的新代码路径

## 五、风险点

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 填充属性序列化兼容旧 shape | 低 | 新字段 `fill?: string`，旧数据无此字段默认透明填充 |
| 乐观锁导致旧客户端被拒绝 | 中 | 首次同步时不验证版本，仅后续更新校验 |
| 橡皮擦裁剪矩形性能 | 低 | 矩形仅4边，计算量远小于画笔路径，无性能问题 |

## 六、验收标准

1. 文字编辑状态下 Ctrl+滚轮缩放，编辑框位置始终在文字上方
2. 橡皮擦扫过矩形/圆/箭头时，图形被删除（非部分裁剪；后续可升级为裁剪）
3. 可绘制有填充色的矩形/圆形，填充色和描边色独立可配
4. 选中图形后 Ctrl+C 复制、Ctrl+V 粘贴，新图形偏移 20px
5. 画布显示可切换的网格背景
6. 两人同时编辑同一图形，后到者收到冲突提示（非静默覆盖）
